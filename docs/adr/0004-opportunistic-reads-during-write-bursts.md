# ADR-0004：Worker 写入期间机会式读取

- 状态：Accepted
- 日期：2026-10-23
- 决策范围：SerialWorker 的 I/O 调度与 Transport 协议

## 背景

发送队列上限为 256 项，Worker 在同一个 I/O 轮次内连续清空队列，单条写入超时 1 秒。驱动写入较慢时（例如 CH34x 小包约 16 ms），一批 256 条写入可持续数秒，期间完全不读取串口，接收数据只能停留在驱动缓冲区，界面表现为接收停顿甚至溢出。

原设计有意避免“每写一条都等待一次读取超时”，以保持发送吞吐；因此不能简单地在每次写入后插入常规阻塞读取。

## 候选方案

1. 限制每轮写入条数，然后执行常规读取：实现简单，但没有接收数据时每条批次都要等待完整读取超时，显著降低发送吞吐。
2. 每次写入后执行常规阻塞读取：接收最及时，但每条写入都可能等待 50 ms，吞吐不可接受。
3. 增加非阻塞的待读字节查询，只有确实有数据时才以零超时读取：无接收数据时不改变突发写出行为，有数据时在写入之间及时派发。

## 决策

采用方案 3。

- `Transport` 增加只读属性 `bytes_available`，返回接收缓冲区中尚未读取的字节数，不发起阻塞读取。
- `SerialTransport` 通过 pyserial 的 `in_waiting` 实现，并将驱动异常映射为领域错误。
- `SerialWorker` 每完成一条写入并确认端口仍打开后查询 `bytes_available`；大于零时调用一次 `read(..., timeout=0)`，把数据交给 `on_bytes_received()`，然后继续处理写队列。
- 队列清空后仍使用原有 50 ms 超时读取；停止请求仍优先于后续写入和机会式读取。
- `bytes_available` 查询失败按 I/O 错误处理：上报错误、设置停止事件并结束 Worker。

## 后果

优点：

- 接收调度间隔从“整批写入完成”缩短到“单次写入完成”，持续发送时不会长期饿死接收。
- 没有待读数据时不增加读取调用，发送吞吐与原有突发写出行为一致。
- 每次只读取一个块，避免接收反压导致写队列长期得不到处理。

约束：

- 每次写入后多一次 `bytes_available` 查询；真实串口上是一次底层缓冲查询。
- `Transport` 协议新增成员，所有实现和测试替身必须同步。
- 单次写入本身阻塞时（最长 1 秒）仍无法读取，这是串口驱动调用的固有边界。

## 验证

- 写入突发期间先注入接收数据，测试断言读取发生在两条写入之间，且数据被派发。
- 无接收数据的 32 条突发仍连续写出，不插入读取调用。
- 覆盖 `bytes_available` 抛领域错误和未预期异常两条失败路径。
- 全量 pytest、Ruff 与文档同步检查通过。
