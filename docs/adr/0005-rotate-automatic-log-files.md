# ADR-0005：自动日志按大小轮转

- 状态：Accepted
- 日期：2026-10-23
- 决策范围：自动日志文件生命周期、LogSink 协议与文件命名

## 背景

自动日志在连接期间持续追加，原先没有单文件大小上限。长时间高速接收会生成数百 MiB 的单个文件，发布验收中累计达到 631 MiB；这类文件在编辑器、传输和归档时都不便处理，也可能掩盖磁盘空间持续增长的问题。

## 候选方案

1. 设置会话总磁盘上限，达到后停止自动日志：能限制总量，但会丢失后续数据，需要额外的用户提示与恢复策略。
2. 保持单文件无上限：实现最简单，但问题不变。
3. 按单文件大小轮转，保留全部分片：不丢数据，每个文件大小可控，由用户自行管理磁盘。

## 决策

采用方案 3。

- `LogSink` 增加只读属性 `bytes_written`，返回当前文件累计写入字节数；CSV 统计表头。
- `LogService` 增加 `max_file_bytes`，默认 `64 MiB`。
- 一条记录写入后若当前文件达到上限，立即刷新、关闭并让同一 sink 打开下一个分片。
- 首个文件名为 `QSerialTool_<端口>_<时间>.<ext>`，后续分片依次追加 `_1`、`_2`；不自动删除旧分片。
- 轮转前强制刷新；轮转失败与会话错误处理一致：停用自动日志、上报错误，串口 I/O 继续。
- 手动导出仍写入单个目标文件，不参与自动日志轮转。

## 后果

优点：

- 单个日志文件大小有界，便于打开、复制和归档。
- 不丢失数据，轮转对记录格式透明。
- `bytes_written` 由各 sink 精确统计，不依赖原始字节估算。

约束：

- 一次长会话仍会产生多个文件，总磁盘占用没有硬上限，需要用户自行清理。
- 文件数量增加，自动化脚本按目录统计时需累计所有分片。
- `LogSink` 协议新增成员，所有实现与测试替身必须同步。
- 轮转后 `LogService.path` 指向新分片，界面日志状态可能需要等到下一次状态刷新才显示新路径。

## 验证

- 单测以极小上限强制轮转，断言新分片命名、路径更新与旧文件内容保留。
- CSV/TXT sink 单测断言 `bytes_written` 在写入后增加，关闭后保持最后值。
- 全量 pytest、Ruff 与文档同步检查通过。
