# ADR-0006：会话关闭改为异步完成

- 状态：Accepted
- 日期：2026-10-23
- 决策范围：SessionController 关闭接口、标签移除流程与应用退出流程

## 背景

原先关闭标签或退出应用时，UI 线程直接调用 `SessionController.close(force=True)`，内部对 Worker 执行 `join(1.5 s)`。单标签最坏阻塞 1.5 秒，多标签按数量串行叠加；串口驱动阻塞或写入超时时，界面会明显卡死。批量关闭优化只减少了多标签的叠加，没有消除 UI 线程等待。

## 候选方案

1. 保持同步关闭，仅缩短等待时间：实现最简单，但无法消除卡顿，且缩短超时可能让 Worker 在窗口销毁后继续运行。
2. 在 UI 线程使用嵌套事件循环/`processEvents()` 等待后台线程：界面能重绘，但重入风险高，容易触发重复关闭、菜单重入和对象生命周期问题。
3. 增加异步关闭接口，由 Worker 停止事件推进状态，UI 等待完成信号或轮询状态后再移除对象。

## 决策

采用方案 3。

- `SessionController.begin_close(force)` 只请求停止并推进到 `DISCONNECTING`（可转换时），立即返回；`on_stopped()` 在 Worker 线程完成尾字节、日志和 `CLOSED` 状态收尾。
- 新增 `is_closed` 属性；关闭完成使用线程事件通知，重复收尾幂等。
- 保留同步 `close(force, timeout)` 供测试和非 UI 调用，内部复用 `begin_close` 并等待关闭事件；超时后仍强制完成状态收尾。
- `SessionTab` 新增 `closed` 信号；`MainWindow` 在收到该信号后才移除标签、注销会话并 `deleteLater()`，避免 Worker 回调指向已销毁的 Qt 对象。
- 窗口退出时先 `begin_close_all()`，用 `QTimer` 每 50 ms 检查所有会话 `is_closed`；全部完成后关闭窗口，超过 2 秒记录警告并强制收尾。
- 等待期间不使用嵌套事件循环，也不阻塞 UI 线程。

## 后果

优点：

- 关闭标签和退出应用期间界面保持响应，可按正常事件循环重绘和处理输入。
- 标签只在 Worker 真正停止后销毁，避免跨线程回调访问已释放对象。
- 同步关闭语义保留，现有测试和内部调用无需改写。

约束：

- 会话生命周期多了一个“已请求关闭、等待 Worker 停止”的阶段；调用方必须使用 `is_closed` 或 `closed` 信号判断完成，不能只依赖 `close()` 返回。
- 退出超时后仍可能留下未退出的非 daemon Worker 线程；这是驱动层阻塞的兜底路径，会记录警告。
- 标签关闭是异步的，用户会短暂看到“正在断开”状态。

## 验证

- UI 测试使用阻塞读取的 Transport，断言标签在 Worker 停止前保留、状态为 `DISCONNECTING`，释放后自动移除并进入 `CLOSED`。
- 窗口关闭测试断言事件先被拒绝、窗口保持可见，Worker 停止后窗口才真正隐藏。
- 全量 pytest、Ruff 与文档同步检查通过。
