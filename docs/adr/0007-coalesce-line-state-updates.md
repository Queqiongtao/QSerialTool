# ADR-0007：DTR/RTS 控制状态合并

- 状态：Accepted
- 日期：2026-10-23
- 决策范围：SerialWorker 控制命令队列

## 背景

ADR-0001 为 DTR/RTS 使用独立控制队列，并注明队列无界但元素是固定布尔命令。实际使用中，界面可能在短时间内连续切换线路状态；虽然命令体积小，但无界队列仍会随切换次数增长，Worker 还会逐条执行已经过时的中间状态。

线路状态的语义是“最终值”，中间状态没有保留价值，与必须逐条处理的串口写数据不同。

## 决策

- 移除无界控制队列，改为受 `Lock` 保护的“最新状态槽”。
- `set_line_state()` 只覆盖槽中的最新一份命令，不阻塞 UI。
- Worker 每个 I/O 轮次读取并清空该槽；如果期间有多次切换，只应用最后一份。
- 控制状态的错误处理保持不变：领域错误或未预期异常都上报 `on_io_error()` 并停止本批处理。

## 后果

优点：

- 控制状态内存占用固定，不随切换次数增长。
- Worker 不再执行已经过时的中间线路状态，减少无意义驱动调用。
- UI 调用 `set_line_state()` 仍然非阻塞。

约束：

- 连续切换时中间状态可能被跳过；这是线路状态“最终值”语义的预期结果。
- 如果需要逐条记录线路状态变化，必须由调用方另行记录，不能依赖 Worker 队列。

## 验证

- 在首次写入阻塞期间连续设置三次 DTR/RTS，释放写入后只应用最后一次状态。
- 原有线路状态读写、错误上报与停止流程测试保持通过。
- 全量 pytest、Ruff 与文档同步检查通过。
