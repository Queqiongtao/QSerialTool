# ADR-0009：终端逐键发送模式

- 状态：Accepted
- 日期：2026-11-04
- 决策范围：SessionPreferences、TerminalOutput、TerminalInlineInput、TerminalSendMenu

## 背景

现有终端视图采用本地行缓冲：按键先写入本地草稿，按回车时才把整行和换行一次发送。这样便于本地编辑和中文输入，但设备收不到实时的 Tab 键，无法触发 Linux shell 的 readline 补全；`Ctrl+C`、`Ctrl+D`、`Ctrl+R`、`Ctrl+U/K/W` 等控制键也无法原样透传。

Linux 串口终端需要的是逐键发送：按键立即写入串口，由设备回显并维护远端行编辑状态。直接替换现有行缓冲会破坏中文输入、发送历史、本地编辑和既有测试，因此需要可选的输入模式。

## 候选方案

1. 只特殊处理 Tab：仍无法解决输入前缀未发送、其他控制键缺失和远端行编辑问题。
2. 把终端视图全部改成逐键发送：行为最接近真实终端，但破坏现有行缓冲和本地草稿，兼容性差。
3. 每个标签可选“行缓冲”或“逐键发送”，默认行缓冲：保留现有行为，同时覆盖 Linux shell 场景。

## 决策

采用方案 3。

- `SessionPreferences` 新增 `terminal_input_mode`，取值 `line`/`raw`，默认 `line`；旧配置缺省为 `line`，不提升 schema 版本。
- 终端“发送设置”菜单新增“输入”子菜单；逐键模式按标签保存，重启恢复。
- 逐键模式不维护本地草稿，所有按键通过 `TerminalInlineInput` 的文本/原始字节通道立即发送；回车沿用“换行”设置。
- 常用键映射：Tab `09`、Backspace `7F`、Esc `1B`、方向键/Home/End/Delete 使用 xterm 序列、`Ctrl+A–Z` 发送 `01–1A`、`Ctrl+[ \ ] ^ _` 发送 `1B–1F`、`Ctrl+Space` 发送 `00`。
- 逐键模式终端优先：终端输出有焦点时接管 `Ctrl+A–Z` 的 `ShortcutOverride`，包括 `Ctrl+T/W/L/Q`；应用操作改用按钮和菜单。`F1` 帮助和字号快捷键不接管。
- 复制粘贴采用标准终端习惯：`Ctrl+C` 发送中断 `03`，`Ctrl+Shift+C` 复制，`Ctrl+Shift+V` 粘贴，`Ctrl+V` 发送 `16`。
- 输入法只发送已提交文本，不发送预编辑文本；逐键模式依赖设备回显，设备关闭回显时界面不会显示输入。
- 逐键模式与 HEX 格式互斥：逐键模式按文本编码发送，HEX 只用于行缓冲；加载到 `raw + hex` 的旧/异常配置时自动切回文本。
- 切换输入模式会清空未发送的本地草稿，避免本地草稿与远端行状态不一致。
- 逐键输入暂不自动写入发送历史；历史菜单中的条目点击后直接发送。逐键模式的所有方向键都透传给设备，`Shift+↑/↓` 不再召回本应用历史。

## 后果

优点：

- Linux shell 的 Tab 补全、列出命令、`Ctrl+C` 中断和 readline 行编辑可用。
- 行缓冲模式完全保留，现有用户和配置不受影响。
- 输入模式按标签独立保存，可与视图模式、换行设置组合使用。

约束：

- 逐键模式没有本地回显，设备必须回显；否则用户看不到输入。
- 终端获得焦点时会优先接收 `Ctrl+T/W/L/Q` 等组合键，应用快捷键需要改用菜单或按钮。
- 每个按键可能产生一条 TX 记录，日志粒度比行缓冲更细。
- 切换模式会丢弃未发送草稿；切换前需要用户自行处理。
- 平台、键盘布局或设备固件对 Backspace、Home/End 等序列可能有差异；首版采用 xterm 默认序列。

## 验证

- 键位映射单元测试覆盖 Tab、回车、退格、方向键、导航键、`Ctrl+A–Z`、AltGr 和未知键。
- 终端 UI 测试覆盖逐键发送、Tab 即时发送、控制键、复制粘贴、输入法提交、模式切换、快捷键接管和未连接保护。
- 配置测试覆盖新字段默认值、旧配置迁移和 round-trip。
- Linux 串口/PTY shell 手工验证 Tab 补全、命令列表、`Ctrl+C/D/R/U/K`、退格、方向键和粘贴。
- 全量 pytest、Ruff 和文档同步检查通过。
