## 1. 安装与启动

### 1.1 从源码运行

先按 `README.md` 创建 `.venv` 并安装开发依赖。

Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe -m qserialtool
```

Linux：

```bash
./.venv/bin/python -m qserialtool
```

### 1.2 运行单文件版本

Windows：

```powershell
.\dist\QSerialTool.exe
```

Linux：

```bash
chmod +x ./dist/QSerialTool
./dist/QSerialTool
```

Linux 单文件仍依赖图形和系统库。如果启动时报 Qt `xcb` 平台插件错误，应先安装当前发行版对应的 XCB 运行库。单文件首次启动会解压到系统临时目录，因此启动速度可能慢于源码运行。

## 2. 主窗口

主窗口顶部只有一行标签栏，没有单独的菜单栏和工具栏。

- 标签栏左侧是会话标签，右侧依次是“字号”下拉框、“主题”下拉框、“+”新建按钮和“☰”菜单。
- “字号”下拉框控制接收区和发送编辑器的字体大小（含终端视图），默认“跟随系统”，可选 `9` 到 `24` 的点数；改动立即作用于所有标签页，并随全局配置保存，重启后恢复。
- “主题”下拉框可切换“跟随系统”“浅色”“深色”；切换后立即用新配色重绘接收区并刷新状态条圆点，无需重开标签。
- “+”与“☰”菜单里的“新建会话”等价，快捷键为 `Ctrl+T`；`☰` 菜单还包含“关闭当前会话”和“退出”。
- 每个标签页分为左侧设置面板和右侧收发区，右侧上半部分是“接收”，下半部分是“发送”。
- “接收”标题行右侧的“终端/分栏”切换按钮可进入终端视图：接收文本按终端语义渲染，支持 CR 行覆盖、退格、换行、ANSI 颜色、光标移动和清屏，不添加应用自己的提示符；设备输出 `#` 后光标就在 `#` 后，直接输入并按回车发送。终端模式没有独立发送行或发送按钮，每个标签独立保存该切换。接收文本中的 IPv4/MAC、URL、邮箱，以及整词匹配的关键字（OK/SUCCESS/PASS 绿、ERROR/FAIL 红、WARN 黄，大小写不敏感）会用主题高亮色标出，设备已用 ANSI 设色的字符保持原色；终端标题行的“高亮”勾选框可整体关闭这些标记（默认开启，随标签保存）。
- 设置面板折叠按钮位于“接收”标题行最左侧；收起后只保留收发区。
- 底部状态条显示状态、端口和 RX/TX 字节数，并用圆点颜色区分状态：灰色为未连接、橙色为连接中或断开中、绿色为已连接、红色为错误。
- 未连接时状态条上的端口跟随端口输入框内容实时更新，并带上设备描述（例如 `COM5 (USB-Enhanced-SERIAL CH343)`）；连接后显示实际使用的端口。
- 标签可以拖动排序，用标签上的关闭按钮或 `Ctrl+W` 关闭当前标签。
- 双击标签或右键标签选“重命名…”可以自定义会话名称；名称会随配置保存，重启后按新名称恢复，最长 40 个字符，留空或超长会提示错误。
- 窗口最小尺寸为 900×600；窗口变矮时设置面板内部可用滚动条访问完整内容。

常用命令：

| 操作 | 快捷键 |
|---|---|
| 新建会话 | `Ctrl+T` |
| 关闭当前会话 | `Ctrl+W` |
| 退出程序 | `Ctrl+Q` |
| 发送当前内容 | `Ctrl+Enter` |

窗口大小、位置、活动标签、主题、侧栏状态、分隔比例、各标签视图模式和其余偏好会在关闭后保存。下次启动恢复标签和参数，但不会自动连接串口。

## 3. 串口设置与连接

每个标签使用独立的串口连接。左侧“串口设置”面板包含端口、波特率、数据位、校验位、停止位、流控、编码、DTR/RTS 和连接按钮。

- 端口列表在未连接时每 30 秒自动刷新一次；也可以点端口框右侧的 ⟳ 按钮立即重新枚举，端口组合框还可以手动输入设备名。
- 列表项会显示「设备名 · 设备描述」（例如 `COM5 · USB-Enhanced-SERIAL CH343`），便于分辨是哪个设备；端口框本身只显示端口名，描述过长时把鼠标停在端口框上可看完整内容。
- 默认波特率为 `115200`，也可输入其他正整数。
- 数据位支持 `5`、`6`、`7`、`8`。
- 校验位支持无校验、偶校验、奇校验、标记和空格。
- 停止位支持 `1`、`1.5`、`2`。
- 流控支持无流控、XON/XOFF、RTS/CTS、DSR/DTR。
- 编码支持 `UTF-8`、`GB18030`、`ASCII`，默认 `UTF-8`；它同时用于接收解码和发送编码，修改后需断开并重新连接才生效，已缓冲的旧记录仍按接收时的编码显示。
- 未连接时修改参数只更新当前标签配置；连接后连接参数会锁定，必须先断开才能再次修改。
- DTR 和 RTS 默认为启用，连接期间可以直接切换并立即发送到设备。
- 连接成功后按钮变为“断开”；点击后程序等待工作线程完成读取、日志刷新和串口关闭。

同一进程内不允许两个会话同时占用相同端口。端口不存在、被其他程序占用或当前用户无权限时，界面会显示错误提示，原会话不会导致主程序崩溃。

## 4. 接收显示

接收标题行提供以下控制，左侧是显示与过滤，右侧是操作：

- “文本/HEX”下拉框：在文本和 HEX 显示之间切换。切换只改变界面渲染，不改变原始字节或自动日志。
- “时间戳”：显示或隐藏本地时间，精确到毫秒。
- `RX` / `TX`：控制接收方向和发送方向记录是否显示。
- “暂停”：暂停界面追加和重新渲染；串口读取、内存缓冲和自动日志继续运行。
- “清屏”：确认后清空当前标签的内存缓冲，不删除已经写入的自动日志。
- “自动滚动”：控制新记录到达时是否滚动到底部。

接收内容使用等宽字体，便于对齐 HEX 字节和日志列。分栏视图下可拖动分隔条调整接收区与发送区的高度比例；终端视图按终端语义渲染 RX 文本，输入草稿跟随设备光标，适合持续查看设备输出并快速输入。

文本编码在“串口设置”的“编码”下拉框中选择，默认 `UTF-8`；若设备使用其他编码，可切到 `GB18030` 或 `ASCII`，也可以先用 HEX 模式核对原始字节。接收和发送使用不同颜色区分方向：浅色主题为绿色 RX、蓝色 TX，深色主题使用对应的亮色，均保证正文对比度。深色主题的占位提示和禁用文字经过单独调校，避免与正常文字混淆。

内存缓冲最多保留 `100,000` 条记录或 `32 MiB` 原始数据，超过任一限制时优先淘汰最旧记录。清屏只清空当前内存内容，不重置进程累计的 RX/TX 字节统计。

界面只渲染最近 `2000` 条记录，更早的内容仍保留在内存缓冲和导出文件中；接收区顶部会用一行“…”提示说明被隐藏的记录数。切换显示模式、时间戳或方向过滤只重绘这段窗口，因此大缓冲下操作依然流畅。

## 5. 发送数据

分栏视图下，发送标题行分成两行：第一行是“格式”“换行”和“发送”按钮，第二行是“历史”、周期间隔和周期按钮。发送编辑器同样使用等宽字体，HEX 模式下便于核对字节。终端视图不显示发送区，也不显示时间戳、RX/TX 过滤和日志前缀，直接在接收流末尾输入并按回车发送；按 ↑/↓ 召回发送历史，多行粘贴会按非空行依次发送。终端顶部“发送设置”菜单可切换文本/HEX、换行和最近历史，周期发送只在分栏视图使用。发送成功后本地草稿立即移除，命令是否留在画面中取决于设备回显。新建会话默认选择 LF；空输入按回车时，“无换行”不发送，CR/LF/CRLF 发送对应换行字节，不会弹出空数据错误。

### 5.1 文本发送

文本模式把编辑器内容按当前会话文本编码转换为字节，默认编码为 `UTF-8`。编辑器为空时提交不会调用空 bytes 发送：无换行时无操作，配置 CR/LF/CRLF 时发送对应换行字节；空内容不会加入历史。

### 5.2 HEX 发送

HEX 模式接受连续十六进制字符或带空白分隔的字节，例如：

```text
AA 01 FF
```

也可以写成：

```text
AA01FF
```

HEX 数据必须由完整字节组成；奇数长度或包含非法字符时会阻止发送并显示错误。显示和日志中的 HEX 统一使用大写、空格分隔格式。

### 5.3 换行策略

发送时可以选择：

- “无换行”：不追加任何字节。
- `CR`：追加 `0D`。
- `LF`：追加 `0A`。
- `CRLF`：追加 `0D 0A`。

新建会话默认选择 `LF`，已有会话保留已保存的设置。终端和分栏视图共用该策略，对文本和 HEX 数据都会生效。

### 5.4 发送历史与周期发送

- 成功发送非空内容后，内容会加入最多 `100` 条的历史记录。
- 连续重复发送同一内容不会重复加入历史。
- 历史下拉框显示最新的条目；选择后回填编辑器，不会自动发送。
- 周期间隔允许 `10 ms` 到 `86,400,000 ms`，默认 `1000 ms`。
- 只有已连接且编辑器非空时才能启动周期发送。
- 周期发送不会重复写入发送历史。
- 断开连接或关闭标签时，周期发送会停止。

## 6. 自动日志与导出

日志设置位于左侧设置面板下半部分。自动日志只能在没有连接时修改；修改后的设置用于下一次连接。

### 6.1 自动日志

- 可选择 `CSV` 或 `TXT`。
- 默认目录是当前用户主目录下的 `Documents/QSerialTool/Logs`，也可以手动选择其他目录。
- 每次成功建立连接后创建新文件；断开时刷新并关闭。
- 文件名格式为 `QSerialTool_端口名_YYYYMMDD_HHMMSS.扩展名`。端口名中的非法文件名字符会替换为下划线，重名时追加序号。
- 日志写入失败时会在界面报错，但不会主动中断串口收发。

CSV 使用 UTF-8 BOM，字段顺序为：

| 字段 | 含义 |
|---|---|
| `timestamp` | 本地时间，精确到毫秒并包含时区偏移 |
| `direction` | `RX`、`TX` 或 `SYSTEM` |
| `encoding` | 记录使用的文本编码 |
| `text` | 按指定编码得到的文本 |
| `hex` | 原始字节的大写 HEX 文本 |

TXT 使用 UTF-8，每行格式为：

```text
[本地时间] 方向 [编码] 文本
```

文本无法表示原始字节时，HEX 字段或 HEX 显示模式仍可用于核对数据。

### 6.2 导出当前缓冲

“导出当前缓冲”把当前标签内存中的全部记录写入所选路径，文件格式取当前日志格式下拉框。导出不会清空缓冲，也不会停止自动日志。

## 7. 配置、退出与恢复

### 7.1 配置位置

Windows 默认路径：

```text
%APPDATA%\QSerialTool\settings.json
```

Linux 默认路径：

```text
${XDG_CONFIG_HOME:-$HOME/.config}/QSerialTool/settings.json
```

配置使用版本化 JSON，保存主题、窗口布局、活动标签、串口参数、显示偏好、日志偏好、发送格式、换行、周期间隔、发送历史和视图模式。旧版配置缺少视图模式时按分栏视图恢复。

### 7.2 写入与损坏恢复

- 配置变更后延迟约 `500 ms` 合并写入，关闭程序时立即刷新。
- 写入采用临时文件替换；已有配置会保留为同目录的 `.bak` 文件。
- 配置损坏或版本不受支持时，程序把原文件复制为 `settings.corrupt.<UTC时间>.json`，随后按无配置状态启动。
- 单个标签配置无效时会跳过该标签；其他有效标签仍可恢复。
- 启动恢复只还原参数，不会自动连接或占用端口。

### 7.3 关闭程序

关闭仍有活动连接的会话时，程序会要求确认。退出时所有会话被强制关闭，自动日志刷新后写入磁盘。

## 8. 常见问题

### 端口列表为空

1. 检查 USB 转串口设备驱动和设备管理器。
2. 点端口框右侧的 ⟳ 按钮立即重新枚举，或等待最多 30 秒自动刷新。
3. Linux 下确认设备节点存在，例如 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。

### 连接失败并提示端口被占用

关闭其他串口工具，并检查本应用其他标签是否已经连接同一端口。修改参数后必须断开并重新连接才会生效。

### Linux 提示权限不足

确认当前用户能够访问对应设备节点。常见做法是把用户加入 `dialout` 或发行版对应的串口用户组，然后重新登录。不要长期使用 `chmod 777` 放宽设备权限。

### 中文显示乱码

界面默认按 `UTF-8` 解码；可在“串口设置”的“编码”下拉框切到 `GB18030` 或 `ASCII`，改完需断开并重新连接。也可改用 HEX 模式确认原始字节，并检查设备实际编码和分行边界。

### 日志文件未生成

确认“自动保存”已启用、目录可写且磁盘空间充足。自动日志只在建立了新连接后开始，修改设置不会为已经连接的会话补建日志。

### 配置被重置

检查配置目录是否存在 `settings.corrupt.*.json`。程序读取失败时会保留损坏文件并重新创建配置；可从 `.bak` 恢复上一次成功保存的内容。

## 9. 已知限制

- 不支持文件发送、日志回放、脚本、Modbus 或协议插件。
- 不提供自动更新、代码签名、遥测和崩溃上报。
- 暂停按钮只暂停界面，不会暂停串口读取、缓冲或日志。
- 终端仿真支持 16 色与 256 色，不支持真彩、alternate screen、滚动区域和 OSC 标题；终端滚动历史上限 5000 行，画面只渲染最近 2000 行。
- Windows 和 Linux 单文件必须分别在对应操作系统上构建。
- 单文件程序未包含自动更新和代码签名；下载后应核对 SHA-256。
